# 触发条件与设备扩展

## 当前实现

触发条件是耳机与特定 2.4G 接收器之间的无线连接状态，不是麦克风活动、音量、音频输入信号或设备名称。

1. `src/Hid.cs` 的 `Hid.Enumerate()` 固定查找 VID `1532`、PID `0552`、Usage Page `FF00`、64 字节输入/输出报告的 HID 集合。
2. `src/LinkProtocol.cs` 的 `HeadsetSensor` 打开匹配接收器，发送只读 E3 状态查询，要求成功 ACK 的序列号与请求一致，也接收被动无线连接事件。
3. 已验证的值 `01` 表示连接、`00` 表示断开；找不到接收器时为缺失。45 秒未获得有效状态时为未知，保留当前设备。
4. `src/Engine.cs` 的 `SwitchPlanner` 把连接状态转为耳机/桌面路由，输出与麦克风使用同一路由，各自切换和校验。

有多个匹配接收器时当前实现保留未知状态，不会任意挑选其中一个。

## 可以更换什么

设置中可以更换连接和断开后的播放设备、麦克风。关联播放设备只作为耳机输出可用性的附加检查：即使 HID 报告连接，它不可用时也会回到桌面路由。

更换关联播放设备不会改变监听的 HID 接收器。当前版本没有通用的“触发设备”选择，也不监听麦克风声音。

## 如何扩展为其他触发设备

以下是后续实现方向，尚未包含在 v1.2.0：

| 设备类型 | 对应检测方式 | 要验证的边界 |
| --- | --- | --- |
| 有线 USB 耳机、声卡、扩展坞 | 配置固定设备标识，监听系统插拔或音频端点可用性 | 实际插拔与重装驱动后的标识变化 |
| 蓝牙耳机 | 配置目标设备，读取系统实际连接状态 | 已配对与实际连接的区别、播放/通话端点变化 |
| 接收器长期插着的 2.4G 耳机 | 按型号增加无线链路协议适配 | 耳机关机时接收器仍在，必须验证真实无线状态 |

建议将检测拆为统一接口，输出 `Connected`、`Disconnected`、`Unknown` 等状态；为 HID、蓝牙连接和设备插拔各写检测器。设置再增加“触发设备”和“检测方式”，保留现有的连接/断开设备组。用户选择检测器后，才启用与它兼容的设备列表。

现有 HID 适配器应继续只发已验证的只读命令。另一种接收器不能只替换 VID/PID 后继续发送 E3，必须先确认其协议，并用真实开关机验证，再接入现有路由层。
